# 02 — تحليل التهديدات وحالات الإساءة (Threat / Abuse Case Analysis)

## 2.1 المنهجية

نستخدم مزيجًا من:
- **Abuse Cases** (إساءة من مستخدمين شرعيين — المطلع الداخلي Insider). هذا هو التهديد الرئيسي لهذا المنتج.
- **STRIDE** للتهديدات التقنية الخارجية (انظر [13](13-security-privacy-deployment.md)).

كل حالة إساءة لها ضوابط من ثلاثة أنواع:
- **P (Prevent):** يمنع أو يصعّب الفعل.
- **D (Detect):** يكشفه بعد وقوعه.
- **R (Respond):** ماذا يحدث عند الكشف.

و**مخاطرة متبقية (Residual)** صريحة — لأن كل ضابط له حدود.

**قاعدة:** كل حالة إساءة هنا تتحول إلى **اختبار آلي** (Abuse Case Test) في [14](14-testing-strategy.md).

## 2.2 الفاعلون (Threat Actors)

| الفاعل | الدافع النموذجي | القدرات |
|---|---|---|
| فني ميداني غير نزيه | سرقة مواد، إثبات عمل لم يُنجز، ساعات إضافية | هاتف مسجل، عهدة مواد، وصول فعلي للأصول |
| مسجّل أصول غير نزيه | خلق "مفاتيح" لصرف لاحق | ملصقات QR، صلاحية إنشاء مسودات |
| مشرف غير نزيه | محاباة، تقاسم عائد، التغطية على فريقه | إسناد، مراجعة، إغلاق |
| أمين مخزن غير نزيه | سرقة مخزون، صرف وهمي | حركات المخزون، الجرد |
| مدير قسم غير نزيه | تمرير مصروفات، تغطية | موافقات عالية، Break Glass |
| مدير نظام / DBA | أي شيء تقني | وصول للخوادم وقاعدة البيانات |
| سارق هاتف / مهاجم خارجي | بيانات، تخريب | جهاز مسروق، الإنترنت |
| **النظام نفسه** | — | أخطاء برمجية، إيجابيات كاذبة، قواعد سيئة |

## 2.4 تحليل التواطؤ (Collusion)

الفصل بين الصلاحيات يهزم الفرد. **لا يهزم التواطؤ.** السؤال الصحيح: ما الذي يبقى صامدًا عندما يتواطأ شخصان؟

| المتواطئون | ما الذي ينجحون فيه | ما الذي يبقى صامدًا |
|---|---|---|
| فني + مشرف | إغلاق إصلاح وهمي أو مضخم | Core Return (يتطلب قطعة تالفة حقيقية) · المخزن مستقل عنهما · Random Audit من مدقق خارج القسم · pHash · الجولة الليلية (إذا نفذها شخص ثالث) |
| فني + أمين مخزن | صرف لعهدة ثم "استهلاك" وهمي | يجب أن يمر الاستهلاك بأمر عمل له أصل وأدلة ومشرف → يحتاجون الشخص الثالث · تحليل الاستهلاك مقابل الأعطال على مستوى المنطقة · الجرد المفاجئ من طرف ثالث |
| مسجل + معتمد | أصول وهمية | العينة الميدانية المستقلة · الملصقات عهدة · الأصل الوهمي لا "يتعطل" دون فني ومشرف → يحتاجون أشخاصًا إضافيين |
| مشرف + مدير قسم | تمرير أي شيء داخل القسم | المدقق مستقل عن القسم · Break Glass مرئي · سلسلة الأدلة لا تُحذف · التحليل على مستوى القسم مقابل أقسام أخرى |
| أي اثنين + مدير النظام | تعديل البيانات | التثبيت الخارجي للسجل عند جهة لا يملكها أي منهم |

**التوصيات التنظيمية (ليست تقنية لكنها ضرورية):**
1. **المدقق يتبع جهة مستقلة** (رقابة داخلية/مكتب التدقيق)، لا مدير القسم.
2. **الجولة الليلية** ينفذها فريق مختلف عن فريق الإصلاح، أو تُدوّر بين الفرق.
3. **تدوير المناطق** بين الفنيين والمشرفين دوريًا (يكسر العلاقات الثابتة).
4. **التثبيت الخارجي** للسجلات يُسلم لجهة رقابية لا يملكها فريق التقنية.

## 2.5 ما لا يستطيع النظام حمايته (بصراحة)

- تواطؤ **كل** السلسلة (فني + مشرف + مخزن + مدقق + مدير).
- مواد سائبة صغيرة القيمة (أشرطة لاصقة، براغٍ) — لا تستحق تكلفة الضبط.
- أعمال تُنجز فعلًا ولكن بجودة رديئة متعمدة (لتتعطل قريبًا وتُطلب مجددًا) — يُكشف جزئيًا عبر قاعدة إعادة العمل (Rework within 30 days) لكن لا يُمنع.
- الضغط الإداري الشفهي خارج النظام.

الهدف هو أن يصبح كل ما سبق **أغلى وأخطر وأوضح أثرًا**، لا مستحيلًا.
