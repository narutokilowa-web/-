# 13 — الأمن، الخصوصية، والنشر

## 13.1 الهدف الأمني

- المرجع: **OWASP ASVS 4.x/5.x — المستوى 2** للويب والـ API، و**OWASP MASVS (L1 + R جزئيًا)** للموبايل.
- اختبار اختراق مستقل **قبل الإنتاج** (نهاية Phase 1) وبعد كل تغيير معماري كبير.

## 13.2 نموذج STRIDE (مختصر — التهديدات التقنية)

| الفئة | التهديد | الضوابط الأساسية |
|---|---|---|
| **S**poofing | انتحال مستخدم / جهاز | OIDC + MFA للأدوار الحساسة · Device binding · Refresh tokens مرتبطة بالجهاز (DPoP أو ما يعادله) · قفل الحساب |
| **T**ampering | تعديل بيانات أو أدلة | أوامر عبر State machine فقط · hash عند الالتقاط · WORM · Audit chain · TLS |
| **R**epudiation | "لم أفعل ذلك" | Audit في نفس المعاملة، مع المستخدم + الجهاز + الأمر الأصلي |
| **I**nformation disclosure | تسريب بيانات شخصية/أدلة | صلاحيات على مستوى السجل · RLS · روابط موقعة قصيرة العمر (5 دقائق) للصور · تشفير أثناء النقل والتخزين · قناع الحقول الحساسة |
| **D**enial of service | إغراق الـ API / الرفع | Rate limiting (لكل مستخدم/جهاز/IP) · حدود حجم الطلب والملف · مهلات · طوابير خلفية للمعالجة الثقيلة |
| **E**levation of privilege | تجاوز الصلاحيات | الصلاحيات من القاعدة لا من الـ Token · اختبارات مصفوفة الصلاحيات الآلية · SoD · منع منح الذات · Four-Eyes لمنح الأدوار |

## 13.3 الضوابط التفصيلية

### الهوية والجلسات
- Keycloak: MFA (TOTP، ويُفضل WebAuthn/مفاتيح أمان للإدارة)، سياسة كلمات مرور وفق NIST 800-63B (طول لا تعقيد، فحص ضد كلمات مسربة)، قفل تدريجي.
- الويب: Authorization Code + PKCE؛ الرموز في ذاكرة/كوكي `HttpOnly; Secure; SameSite=Strict` عبر BFF خفيف أو نمط مكافئ — **لا Tokens في localStorage**.
- مهلة خمول: 15 دقيقة للأدوار الحساسة، 60 للبقية.
- إنهاء كل الجلسات عند تعطيل المستخدم أو سحب دور حساس.

### الـ API
- التحقق من المدخلات على الخادم (FluentValidation أو ما يماثل) لكل أمر — المخطط + قواعد العمل.
- ORM بمعاملات (Parameterized) فقط؛ لا SQL نصي مُركب.
- CORS مقيد بأصل الويب.
- ترويسات أمنية: CSP صارمة، HSTS، `X-Content-Type-Options`، `Referrer-Policy`، `Permissions-Policy`.
- رسائل الأخطاء لا تكشف تفاصيل داخلية.
- كل Endpoint له اختبار صلاحيات (مولد من المصفوفة).

### رفع الملفات
1. رفع مباشر إلى S3 عبر رابط موقع محدد (المفتاح، النوع، الحجم الأقصى 15MB، مدة 15 دقيقة).
2. Bucket استقبال منفصل (Quarantine bucket) غير قابل للقراءة من التطبيق.
3. عامل خلفي: فحص Magic bytes (JPEG/PNG/HEIC فقط للصور) → فحص hash → **إعادة ترميز للمشتقات** (يُزيل أي حمولة مخفية ويزيل EXIF) → ClamAV (للمستندات، وللصور كطبقة إضافية) → نقل الأصل إلى Bucket الأدلة (WORM).
4. العرض دائمًا عبر المشتقات المعاد ترميزها؛ الأصل (بـ EXIF/GPS) يُتاح فقط للمدقق.

### التشفير
- **النقل:** TLS 1.2+ (يُفضل 1.3) في كل مكان، بما فيه الاتصالات الداخلية بين الخدمات إن كانت على شبكة مشتركة.
- **التخزين:** تشفير الأقراص/الحجوم (مستوى البنية) + تشفير جانب الخادم في S3 + تشفير على مستوى العمود لحقول محددة إن وُجدت (أرقام هوية وطنية إن احتُفظ بها — **الأفضل ألا نحتفظ بها**).
- **الموبايل:** SQLCipher + Keystore.
- **النسخ الاحتياطية:** مشفرة، والمفاتيح منفصلة عن النسخ.

### الأسرار
- لا أسرار في المستودع أبدًا (فحص آلي في CI: gitleaks أو ما يعادله).
- MVP: متغيرات بيئة من ملفات محمية على الخادم أو Docker secrets.
- Phase 2+: Vault/OpenBao أو KMS الجهة.
- مفتاح توقيع التثبيت (Anchor key) **لا يملكه فريق التشغيل** — عند جهة التدقيق أو في HSM بصلاحيات منفصلة.

### سلسلة التوريد (Supply chain)
- تثبيت الإصدارات (Lock files)، Dependabot/Renovate، فحص الثغرات (OSV/Trivy) في CI يفشل على الحرج.
- SBOM (CycloneDX) لكل إصدار — كثير من الجهات الحكومية تطلبه.
- صور حاويات بسيطة (distroless/chiseled)، تعمل كمستخدم غير root، فحص الصور.
- التوقيع على الصور (cosign) — Phase 2.

### الأجهزة
- **توصية قوية: أجهزة مملوكة للجهة ومدارة (MDM — Android Enterprise)**: سياسات قفل، منع Developer options / Mock location، مسح عن بُعد، تثبيت التطبيق من قناة الجهة.
- BYOD ممكن تقنيًا لكنه يضعف: كشف Mock، التحكم بالتطبيقات، والخصوصية (الموظف يرفض مراقبة هاتفه الشخصي — حقه). **سؤال مفتوح.**
- كشف الجذر (Root) و Play Integrity API — Phase 2 (مع مراعاة أن بعض الأسواق/الأجهزة لا تدعم خدمات Google — التصميم لا يعتمد عليها كشرط).

## 13.4 الخصوصية

| المبدأ | التطبيق |
|---|---|
| تقليل البيانات | الموقع **عند أحداث الأدلة فقط** · لا تتبع مستمر · لا جهات اتصال/ميكروفون/ملفات الجهاز · لا رقم هوية وطنية إن أمكن |
| تحديد الغرض | بيانات الموقع والصور تُستخدم للتحقق من العمل والنزاهة فقط · **تحظر السياسة استخدامها لتقييم الأداء العقابي الآلي** |
| الإشراف البشري | لا قرار آلي بأثر على الموظف · Flag ← مراجعة بشرية ← حق الرد |
| الشفافية مع الموظف | إشعار خصوصية واضح داخل التطبيق: ماذا يُجمع، لماذا، من يرى، كم يُحفظ · الموظف يرى سجل الأدلة الخاص به |
| الوصول | البيانات الشخصية التفصيلية (إحداثيات الأدلة الأصلية، أداء الأفراد) للمدقق فقط · كل وصول لها يُسجل |
| الاحتفاظ | انظر [09](09-domain-data-model.md#95-الاحتفاظ-بالبيانات-مقترح-أولي--يُعتمد-قانونيًا) · حذف/تعمية مجدولة وموثقة |
| الصور | تنبيه للفنيين بتجنب تصوير وجوه المارة ولوحات السيارات؛ (Phase 3+) تمويه آلي للوجوه في المشتقات العامة |
| تقييم الأثر | **DPIA (تقييم أثر حماية البيانات) قبل التجربة** مع الشؤون القانونية وفق قانون البلد |

## 13.5 خطة النشر

### البيئات

| البيئة | الغرض | البيانات |
|---|---|---|
| `dev` | تطوير محلي (Docker Compose على جهاز المطور) | بذور صناعية |
| `staging` | اختبار تكاملي، UAT، عروض | بيانات صناعية أو مجهولة |
| `pilot/prod` | التشغيل الفعلي | حقيقية |

### طوبولوجيا التجربة (Pilot) — متواضعة عمدًا

```
[VM-1: Edge + App]   4 vCPU · 8GB
   Reverse proxy (Caddy/nginx: TLS, rate limit)
   API (×2 containers) · Worker (×1) · Web (static)
   Keycloak

[VM-2: Data]         4 vCPU · 16GB · SSD
   PostgreSQL 17 + PostGIS (primary) · pgaudit
   pgBackRest → WAL archiving مستمر

[VM-3: Storage]      2 vCPU · 4GB · 1–2TB
   S3-compatible (Object Lock) — أو خدمة S3 من السحابة الحكومية

[VM-4: Ops]          2 vCPU · 4GB
   Prometheus · Grafana · Loki · Alertmanager
   PostgreSQL standby (streaming replica) — يمكن نقله لـ VM منفصل

+ موقع خارجي/منطقة ثانية: نسخ احتياطية مشفرة + Anchor bucket
```

**تقدير الحجم للتجربة (3,000 أصل، ~600 أمر عمل/شهر):** الصور ≈ 600 × 6 × 0.5MB ≈ 1.8GB/شهر. قاعدة البيانات < 5GB في السنة الأولى. **الموارد أعلاه أكثر من كافية**؛ الحجم مختار للهامش والتوافرية لا للحمل.

### الاستضافة
- **سحابة حكومية/وطنية أو مركز بيانات الجهة** — تحدده سياسة سيادة البيانات (سؤال مفتوح).
- التصميم محايد: Docker + PostgreSQL + S3 API + OIDC = يعمل في أي مكان.

### CI/CD
```
PR → build + unit + architecture tests + lint + secrets scan + dependency scan
   → integration tests (Testcontainers) + authorization matrix + abuse-case tests
merge main → build images (signed later) + SBOM → deploy staging (auto) → E2E smoke
release tag → deploy pilot (manual approval — two people: Four-Eyes على النشر أيضًا)
```
- Migrations قاعدة البيانات: أمامية فقط (Forward-only)، متوافقة مع النسخة السابقة من التطبيق (Expand/Contract) لتسمح بالتراجع عن التطبيق دون التراجع عن القاعدة.
- التطبيق الميداني: توزيع عبر MDM أو متجر مُدار؛ **آلية إجبار تحديث** للإصدارات التي بها ثغرة؛ الخادم يدعم إصدارين سابقين من التطبيق على الأقل (الأجهزة لا تتحدث فورًا).

### النسخ الاحتياطي والتعافي

| البند | الهدف (Pilot) |
|---|---|
| RPO (أقصى فقد بيانات) | ≤ 15 دقيقة (WAL archiving) |
| RTO (زمن الاستعادة) | ≤ 4 ساعات |
| النسخ | كامل أسبوعي + تفاضلي يومي + WAL مستمر؛ 3-2-1 (3 نسخ، وسيطتان، واحدة خارج الموقع) |
| الوسائط | Object Lock + تكرار (Replication) لموقع ثانٍ |
| **تمرين الاستعادة** | **شهري إلزامي**، موثق في Runbook — نسخة لم تُختبر استعادتها ليست نسخة |
| التحقق بعد الاستعادة | تشغيل `chain-verifier` على قاعدة البيانات المستعادة |

**ملاحظة:** العمل دون اتصال يجعل النظام مرنًا ضد انقطاع الخادم للفنيين — يستمرون في العمل ويزامنون عند العودة.

### المراقبة والتنبيه
- صحة الخدمات، زمن الاستجابة، معدل الأخطاء، عمق الطوابير، تأخر الرفع، مساحة التخزين، تأخر النسخ الاحتياطي.
- **تنبيهات نزاهة** (منفصلة عن التقنية، تذهب للمدقق): كسر السلسلة، فشل التثبيت، Break Glass، محاولة UPDATE على التدقيق (من سجلات pgaudit).

### الحوادث
Runbooks لـ: فقدان جهاز، اختراق حساب، كسر سلسلة التدقيق، فشل الاستعادة، تسرب بيانات. كل حادثة أمنية/نزاهة لها مالك وإبلاغ خلال مدة محددة.
